The first visual startup run returned immediately to MOS with a level-layout
error. Directed loader instrumentation reduced this to footer stage 8: the
canonical cursor was correctly `0x3925`, but the comparison read absolute RAM
address `0x003925` rather than `w3d_level_package + 0x3925`. Converting the
relative cursor to an arena pointer for the four-byte `E3L1` check, then back
to a relative total, fixed the fault. Inspection of current MOS source also
corrected a misleading API note: `mos_load` always sets carry and silently
caps the read to BC; it does not report an oversize source. This is memory-safe
for the fixed arena, the footer detects short files, and canonical content
ends at the header's validated total size, so any source trailing bytes are
ignored. Transition-time AGNB errors also no longer masquerade as package-
validation errors.
