## Production render contract and atomic mirror

TODO 8e began without disturbing the standalone default. Schema 1 now has one
generated numeric authority for both C++ and eZ80 assembly. It freezes the six
entry IDs, exact 24-byte resource descriptor, 16-byte update header, eight
record layouts, 6,912-byte and 617-record bounds, copied-pixel workspace,
resident asset formulas, and VDPlet error mapping. The full contract is
`agonport/doc/wolf3d-vdplet-production-contract.md`.

The first pure production component is a 5,360-byte render-facing world mirror
with a hard 5,500-byte ceiling. Its two-pass parser validates lengths, record
types, values, slots, duplicates, full-snapshot coverage, level binding and
generation before changing any mirror byte. A full maximal E1-style snapshot
with 64 doors, 149 actor slots and 400 statics is 6,891 bytes. Partial batches
reuse the existing door/actor/static/player wire records.

Publication failure does not strand the client: after application the mirror
marks the generation pending, accepts only the exact same batch fingerprint
for an idempotent retry, and refuses altered or newer generations until pixel
publication is committed. The eZ80 can therefore retain its dirty flags and
consolidated bytes on ERROR without allocating a second resident mirror.

The durable host build verifies synchronized generated contracts and exercises
valid full/partial updates, descriptor validation, exact retry, mutation-free
rejection, bad magic/length/generation/order/type/value, duplicate slots,
missing full coverage, maximal bounds and wrap refusal. All tests pass. This
is contract/parser evidence only; the freestanding production renderer,
package admission, emulator, gameplay, and hardware gates remain open.
