## Pre-code boundary and question

Carmack's literal post widening can replace the next wall height; original
fractional scaling and generated x86/VGA routines also differ from this port.
Those methods remain incompatible as-is and are not silently substituted here.
This asks about a separate optimization supported by existing bytewise row APIs:
for adjacent columns already having equal FULL height, resolved texture ID and
U, their sampled colour is identical on each destination row. Existing
fill_span can write that row segment without changing any texel/height.

General row-major reordering is **not** equivalent: WOLF-GOAL-001's retained
2x2 aliased-row example gives different results. A fast path therefore requires
proven distinct destination addresses and source stability; unproven layouts
must retain the original scalar order. No blanket nonalias claim from current
host output or native scanline-array type is acceptable.

A deliberately narrow possible predicate is a320-byte linear framebuffer, or
rows with x_bias0, pixel_xor0..3 and all240 actual row pointers exactly320 bytes
apart, with checked unsigned address extents. These properties imply distinct
in-range pixels for320-wide rows under that permutation. Require the acquired
texture's complete relevant source range disjoint from the entire target extent;
retain source/frame aliasing on the scalar path. Check actual ABI/runtime row
stability through the render/asset callback lifetime. This is a proposal needing
source verification, not an assumed native guarantee or implemented predicate.

Use identical full-height clipping/fraction and sampler limits; mask texture
colour with63 before fill_span. Keep ID acquisition/release/failure precedence,
statistics, HUD and sprite painter order, private local lifetime, borrowed rows,
PSRAM-safe byte stores and all current admission guards. Overlapping preserve/
colour bits alone do not invalidate a single same-value write to each distinct
pixel, but cannot justify skipped background fills. No wider stores, firmware/
SDK/helper/provider/service extension, unverified provenance flag or height
approximation is selected.
