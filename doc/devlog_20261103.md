# Development log — 2026-11-03

## Render-visible actor activation

The shareware residual audit found one important difference between the DOS
renderer and the write-only Agon split. `WL_DRAW.C::DrawScaleds` sets an
actor's persistent `active` byte after the renderer accepts it. The previous
port scheduled an `ACTIVE_NO` actor only while its area remained connected, so
an actor that had already appeared on screen could go back to sleep after a
door disconnected the area.

Production now performs a conservative CPU-owned promotion immediately before
an actual render submission. It scans only dormant actors, requires a valid
connected area and drawable state, applies the existing player-facing CPU
projection, verifies line of sight with `CheckLine`, and then changes the
actor to `ACTIVE_YES`. Promotion is persistent. Noise and actor-facing
`CheckSight` are deliberately excluded because either can detect an actor
behind the player and would create a false permanent wake-up.

The direct patrol fixture now covers:

- centered unobstructed promotion;
- persistence after area disconnection;
- behind-player rejection;
- wall rejection;
- disconnected-area rejection; and
- a PRT1 benchmark of 1,000 deliberately worst-case full promotions.

Oryx generation 178 passed 624/624 direct-eZ80 checks. Its existing real E1L1
92-frame actor/door route measured 20 ms total (0.217 ms per fixed frame). The
new benchmark measured 158 ms for 1,000 complete visible promotions, or 0.158
ms for one dormant centered actor at a render boundary. This scan is not in
the 30 Hz physics loop; already promoted actors take only the cheap active-byte
skip on later submissions.

reuse test module basenames and local imports.

The exact residual is documented rather than hidden: the original could also
promote when an open neighboring tile was present in renderer `spotvis`. With
no VDP read-back, this implementation waits for the actor center itself to be
accepted, so a corner-peeking actor may wake slightly later. Revisit only if
the neighboring-tile approximation can remain player-facing without copying
the renderer's full visibility hot path onto the eZ80.

The patrol runner was also made portable across current emulator layouts. It
accepts explicit emulator, MOS, and VDP paths, supports an emulator-provided
stock VDP, and can expose emulator output when diagnosing startup failures.
